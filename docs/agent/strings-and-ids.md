# Strings, language files, and the usage registries

## Language files (`lang/*.lng`)

- **`english.lng` is the master** (grflangid 0x01): every string must exist
  there; other languages fall back to it. `russian.lng`, `ukrainian.lng` and
  `bulgarian.lng` are near-complete translations; the rest are partial or
  stubs.
- **Practical rule: add every new string to `english.lng` and `russian.lng`;
  the others are optional.**
- Files are bracketed by `# begin main block` … `# end main block` and divided
  into `# ---…---` banner sections in a fixed order (General strings, params,
  Steam locomotives, …, livery sections, Rail types). Within a section entries
  are sorted case-insensitively by ID and colon-aligned — `scripts/clean-lng.pl`
  re-sorts them automatically.
- Tool-managed markers:
  - `UNUSED_STR_*` — the string is referenced by no `.pnml`; `clean-lng.pl`
    renames it (and renames it back once code references it again). Do not
    delete these by hand.
  - a leading `#` on a translation line — deliberate fall-through to English
    (used e.g. for `STR_GRF_*_NAME` which is just `{TITLE}` everywhere).
- The only custom tag used in strings is `{TITLE}` (value of every
  `STR_GRF_*_NAME`), filled from the build-generated `custom_tags.txt`.

## String ID naming

For a vehicle with NML identifier `<vehid>` (uppercased, `-`→`_`, minus the
leading `_` that escapes digits):

| Pattern | Purpose |
|---|---|
| `STR_NAME_<VEHID>` / `STR_LONGNAME_<VEHID>` | short / verbose purchase-list name |
| `STR_NAME_<SERIES>_SERIES` / `STR_LONGNAME_<SERIES>_SERIES` | group item name |
| `STR_NAME_<SERIES>` | subgroup label for `name_in_group_subgroup` |
| `STR_PURCHASE_HINT_ENGINE_TYPE_*` | traction-type label in hints |
| `STR_SECTIONS_*` | legal consist description |
| `STR_PURCHASE_HINT_FACTORY_*` | builder names (behind `fact_*()` macros) |
| `STR_LV_*` + livery sections | `cargo_subtype` livery labels |
| `STR_START_STOP_*`, `STR_CAN_ATTACH_*` | callback error texts |
| `STR_GRF_<MODULE>_NAME` / `_DESC` | per-GRF header strings |

## The usage registries (`src/IDs_usage`, `src/PNGs_usage`, `src/PNMLs_usage`)

All three are **generated by `scripts/clean-lng.pl` and committed** (CRLF line
endings). Regenerate after any change to vehicles, sprites, includes or
strings; never edit them by hand.

- `IDs_usage` — `ID -> identifier (file)`, one line per numeric train ID from
  124 up. Empty right-hand side = free ID; a duplicate makes the script die.
  This is the **only** duplicate-ID guard in the repo.
- `PNGs_usage` — `png -> (pnml files using it)`, scraped from
  `#define IMAGEFILE` and `spriteset(...)` literals. Empty RHS = unused sprite.
- `PNMLs_usage` — `pnml -> (files including it)`. The fastest way to answer
  "which builds does this file end up in?". Empty RHS = orphan file.

## `scripts/clean-lng.pl`

Run from the repo root: `perl scripts/clean-lng.pl`. It:

1. sorts each `.lng` section and toggles the `UNUSED_STR_` prefix based on
   actual usage in `src/`;
2. lowercases all `.png` / `.pnml` filenames (by renaming the files);
3. regenerates the three usage registries;
4. **dies** on duplicate vehicle IDs, and on strings referenced in code but
   missing from every `.lng` (report written to `lang/_Missing.txt`,
   git-ignored).

Neither `compile.sh` nor CI runs it — the Windows `.bat` flow does. Run it
manually and commit the regenerated files.
